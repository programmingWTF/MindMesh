# 报告

## 什么时候用

| 用户说 | 你产出 |
|---|---|
| 「写个报告」 | 一份结构化文档（Markdown） |
| 「发布一下」 | 一个可访问的链接（**需要先问要不要共享**） |
| 「整理成文档」 | 一份可归档的文件（走 `Skills/Files`） |

## 写作要求

- **先给结论**，再给推导。不要在开头铺垫。
- **结构化**：小标题 + 表格 + 列表。长表格比长段落好读。
- **有数据、有出处**。没有出处就标注「未核实」。
- **长的推导、日志、原始数据 → 放进折叠块**：

```html
<details>
<summary>原始数据</summary>

（大段内容）

</details>
```

- **不要为了显得充实而注水。**删掉没信息量的句子。

## 发布

发布方式取决于你**有没有静态站点**：

| 你有的 | 做法 |
|---|---|
| 什么都没有 | 写成一个文件，走 `Skills/Files` 交付，**或直接贴进对话** |
| GitHub 仓库 | 提交为 Markdown → GitHub 自动渲染；需要网页再开 Pages |
| 自建静态站 | 写入站点目录 → 跑索引脚本 → 给链接 |

### ⚠️ 发布前必须问的一件事

> **「这份内容要不要共享？共享给谁？」**

因为一旦发布，最坏情况是**公开可读**。默认应当**私密**。

| 状态 | 含义 |
|---|---|
| 默认 | 只有你自己能访问 |
| 共享 | 生成一个访问 token / 链接，交给你想给的人 |

## 失败路径

| 症状 | 原因 | 做法 |
|---|---|---|
| 发布后 404 | 权限没登记 / 路径不对 | 检查索引与访问控制，**不要**临时放开全站 |
| 页面样式错乱 | 相对路径 / 缺资源 | 用绝对路径，或内联 |
| 内容太大 | 单文件过大 | 拆多个文件，做索引 |

## 验证

- 链接**自己点一次**（或 `curl` 一次）确认可访问且内容正确；
- 确认访问级别**符合用户的意图**（私密 / 共享）。

> 报告的价值在「别人看完能做决定」。如果读者看完还得问你「所以呢」，那它是草稿，不是报告。
