# 文件交付

## 一次配置，永久可用

在任何对话里传文件都是低效的。**配置一个固定的投递目录**：

```text
<投递目录>      我 → 用户    （用户从这里取文件）
<收件目录>      用户 → 我    （用户把文件放这里）
```

**把这两个路径写进 `06World.md`**，所有 Agent 就能用同一套约定。

> ⚠️ 最常见的事故：**Agent 把文件写进了自己的暂存目录，用户根本看不到。**
> 因此必须有一个**约定好的、被文档化的**投递目录，而不是每次临时决定。

## 交付流程

```bash
# 1. 放到投递目录（用你文档里约定的路径）
cp <产物> "<投递目录>/"

# 2. 权限：让用户/文件服务读得到
chmod 664 "<投递目录>/<文件名>"

# 3. 校验
ls -l "<投递目录>/<文件名>"
```

然后**告诉用户一个明确的位置或链接**，不要只说「已发送」。

## 命名

- 文件名要能自解释：`2026-01-01-季度复盘.pdf` 优于 `report_final_v2.pdf`。
- **不要**用空格和中文标点（跨平台会坏）。用 `-` 分隔。
- 一个交付物一个文件，不要打包成一堆散件。

## 大文件

| 大小 | 做法 |
|---|---|
| < 10 MB | 直接投递 |
| 10 MB ~ 1 GB | 投递 + 给出校验和 |
| > 1 GB | 放外部存储，给出链接 + 校验和 |

```bash
sha256sum <文件>
```

## 失败路径

| 症状 | 原因 | 做法 |
|---|---|---|
| 用户说「没看到」 | **写错了目录** | 核对 `06World.md` 里的约定路径；检查文件权限 |
| 文件名乱码 | 中文/特殊字符 | 重命名为 ASCII + 短横线 |
| 文件权限不对 | `umask` | 显式 `chmod 664` |

## 验证

- [ ] 文件在**约定目录**里（不是你的临时目录）
- [ ] 权限正确（`ls -l` 看到 `rw-rw-r--`）
- [ ] 你给了用户**确切路径或链接**
- [ ] （大文件）给了校验和
