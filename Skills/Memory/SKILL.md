# 记忆

## 记忆在哪

```text
Memory/<你的名字>/          ← 你唯一可以写的地方
Memory/<其他 Agent>/        ← 只读（一般不要读，除非用户明确要求）
```

## 召回：先搜，再读

**永远不要整目录读。**记忆会随时间无限增长。

```bash
# 1. 搜关键词（拿到候选文件）
grep -rIl "<关键词>" Memory/<你的名字>/ | head -20

# 2. 搜到内容再定位（拿到行号）
grep -rIn "<关键词>" Memory/<你的名字>/ | head -40

# 3. 只取需要的那几行
sed -n '10,40p' Memory/<你的名字>/Daily/2026-01-01.md
```

> 用 `ripgrep`（`rg`）会快很多：`rg -n "关键词" Memory/<你的名字>/`

## 建议的分层

| 文件 | 内容 | 何时读 |
|---|---|---|
| `Memory.md` | 当前活跃状态（精简） | 每次会话开始 |
| `Daily/YYYY-MM-DD.md` | 当天发生的事 | 需要时间线时 |
| `Reference-<领域>.md` | 某领域的细节 | 需要细节时 |
| `Learnings.md` | 犯过的错 + 正确做法 | 开工前扫一眼 |

## 写：写文件 > 心理笔记

**不写进文件的东西，会话一结束就不存在了。**

写的时候守住三条：

1. **写结论，不写过程。**「构建用 `pnpm build`」比「我试了三种方式最后发现……」有用。
2. **写清日期与原因。**半年后的你会问「为什么」。
3. **犯过的错单独写。**一条 `Learnings.md` 里的记录，能省掉未来一次同样的失败。

## 这条信息该写到哪？

**判断标准只有一条：它属于谁？**

| 这条信息…… | 写到 |
|---|---|
| 只有我会用到 | `Memory/<我的名字>/` |
| **所有** Agent 都需要知道的事实 | 顶层文档 / `06World.md`（**走 PR**） |
| **所有** Agent 都需要会做的操作 | `Skills/<Name>/SKILL.md`（**走 PR**） |
| 是密钥 | **哪里都别写**（协议第 17 条） |

> ⚠️ 最常见的错误：把「所有 Agent 都该知道的事」只写进了自己的目录。
> 那等于没写——别人不会去读你的记忆。
>
> 反之，把私事写进公共文档同样糟糕。

## 失败路径

| 症状 | 原因 | 做法 |
|---|---|---|
| 搜索结果为空 | 关键词不对 | 换同义词、换语言、搜日期 |
| 找到了但内容自相矛盾 | 两个 Agent 记了不同版本 | **以最近日期的为准**，并在报告里指出矛盾，不要静默覆盖 |
| 记忆目录很大 | 长期没归档 | 见 `Scripts/audit.sh` 的体积报告 |

## 验证

- 你能回答「这条结论是哪天、因为什么记下的」；
- 你写的内容**出现在 `Memory/<你的名字>/` 里**，且 `git status` 只有你的目录有改动。
