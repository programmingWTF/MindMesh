# Prompts / AuthorSkill.md — 让 Agent 设计一个新技能

> **用法**：把分隔线之间的内容整段复制给 Agent，并在 `<需求>` 处描述你想要的能力。

---

我想让**我所有的 Agent** 都获得一个新能力。

**需求**：`<例：把一份 Markdown 转成排版良好的 PDF 并发到我的收件箱>`

请按下面的流程做，**每一阶段结束先停下来给我看结论**。

---

## 阶段 1 · 先判断该不该写成技能

按顺序回答，并给出理由：

1. 这是我**原生就会**的能力吗？（如果是，直接告诉我「用你原生的」，结束）
2. 这个能力会**重复使用**吗？（少于 3 次的话，建议放 `Memory/`）
3. **别的 Agent** 也需要吗？（如果只有我需要，放 `Memory/<我的名字>/`）
4. 有**明确的成功判据**吗？（说不清就不合格）

**给出结论：写成技能 / 不写成技能 + 理由。**

## 阶段 2 · 设计

如果决定写入 `Skills/`，给出：

- `name`（短横线命名，全局唯一）
- `description`：**一句话说明「什么时候用它」**，必须包含我可能会说的**触发词原话**
- 前置条件（凭据 / 命令 / 权限）
- 步骤（编号，可执行）
- 命令 / 代码块（**可直接复制运行**）
- **失败怎么办**（症状 / 原因 / 做法 的表格）
- **验证**：怎么确认成功了

## 阶段 3 · 安全审查

对你自己写的东西过一遍：

- 有没有读取不该读的东西（``` ~/.ssh ```、`.env`、凭据管理器、浏览器 Cookie）？
- 有没有向未说明的域名发送数据？
- 有没有要求 `sudo` / 关闭安全设置 / 执行远端拉取的脚本？
- 有没有把凭据、令牌、内网地址硬编码进去？

**任何一条命中，先修掉再继续。**

## 阶段 4 · 提交

```bash
git pull --rebase
git checkout -b add-skill/<名字>
# 写 Skills/<Name>/SKILL.md
git add Skills/<Name>
git commit -m "add-skill: <名字>

Agent: <我的名字>"
git push -u origin add-skill/<名字>
gh pr create --fill
```

同时更新 `SkillsList.md`（**另开一个 PR**，不要混在一起）。

## 阶段 5 · 回报

告诉我：技能名、它解决什么、怎么验证它有效、以及**它可能失败的情形**。
